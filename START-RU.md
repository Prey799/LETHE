# LETHE ONE 0.7.2 — запуск, настройки и управление сервером

Для обычной установки используйте **LETHE-Setup-0.7.2-x64.exe**; порядок описан в **INSTALL-RU.md**. Инструкция распаковки ниже относится к переносимому архиву.

## 1. Запуск обновления

1. В старой версии нажмите **Отключить**, дождитесь завершения и закройте её, включая значок в трее.
2. Распакуйте новый архив целиком в отдельную папку. Сохраните старую рабочую папку.
3. Откройте **LETHE.exe** двойным щелчком. Не запускайте `LETHE-One.ps1` через PowerShell: основной запуск теперь выполняется EXE.
4. Настройки и защищённый профиль подхватятся из `%LOCALAPPDATA%\LETHE-One` для того же пользователя Windows.
5. Откройте **Настройки**, проверьте расположение полей. Нажмите **Сохранить**.
6. Подключите VPN. При изменении маршрутов Windows запросит UAC; подтвердите его под тем же пользователем, у которого сохранён профиль.

Требуются Windows 10/11 x64, встроенный Windows PowerShell 5.1 и .NET Framework 4.8. Python, Visual Studio и отдельный OpenSSH на клиентском компьютере не нужны. Все папки комплекта должны находиться рядом с EXE.

Теперь `LETHE.exe` — GUI-процесс, внутри которого работает интерфейс. Он не запускает отдельные `powershell.exe` или `cmd.exe` для окна, деплоя, подключения и фонового контроля. Сетевые движки запускаются без консоли. Внутри приложения используется встроенный движок Windows PowerShell; это не требование открывать Shell вручную. UAC является системным запросом прав, а не окном Shell.

## 2. Как устроены настройки

Все параметры находятся в одном окне. Верхние кнопки перемещают к нужному блоку. Если окно не помещается по высоте, содержимое прокручивается, а кнопки сохранения остаются внизу. У полей и подписей есть всплывающие пояснения.

| Блок | Что в нём находится |
|---|---|
| **VPS и SSH** | Адрес управления VPS, SSH-порт, пользователь Linux, выбранный способ входа, проверенный ключ сервера |
| **Caddy** | Домен HTTPS-сайта и VPN, IP входа, IP выхода, назначение портов, контакт для сертификата, профиль доступа |
| **Приложение** | Физический интерфейс Windows, локальный SOCKS5-порт, MTU, число ошибок до отключения и поведение трея |

### Адреса вводятся один раз

- **Адрес VPS для SSH** — куда приложение подключается для установки, проверки и удаления сервера. Укажите адрес, по которому вы уже входите в VPS.
- **IP входа Caddy** — куда подключается VPN. Если это тот же адрес, выберите **IP VPS из блока SSH**. Если у Caddy отдельный IP, выберите **Отдельный IPv4** и введите его.
- **IP выхода** — адрес, который должны видеть внешние сайты. Можно выбрать адрес входа, адрес VPS из блока SSH либо отдельный IPv4.

Поля для отдельных IP появляются только при выборе отдельного адреса. Общий адрес повторно вводить не требуется. Для Caddy нужны именно IPv4; если SSH указан доменным именем, для входа/выхода задайте IPv4 отдельно.

Пример для VPS с двумя адресами: если SSH доступен по `185.203.4.24`, а Caddy принимает VPN на `89.208.96.163`, укажите первый адрес в блоке VPS, второй — как отдельный IP входа Caddy, а для выхода выберите **IP VPS из блока SSH**. Это пример назначения полей: используйте реально работающий SSH-адрес своего сервера.

Изменение IP выхода в клиенте меняет ожидаемый результат проверки, но не перенастраивает существующий VPS. Выделенный выход устанавливается при развёртывании нового сервера.

### Порты имеют разное назначение

| Порт | Где используется |
|---|---|
| SSH, обычно **22** | Вход на VPS для управления; изменяется в блоке VPS |
| **443/TCP** | Вход Caddy для HTTPS-сайта и VPN; фиксирован в этой конфигурации |
| **80/TCP** | HTTP Caddy и получение сертификата; фиксирован в этой конфигурации |
| SOCKS5, обычно **1080** | Только внутри вашего Windows-компьютера; открывать его на VPS или роутере не нужно |

Единого «выходного порта VPS» нет: он определяется сайтом или программой назначения. Разрешённые исходящие порты зависят от конфигурации сервера. Настройки 80/443 не изображены как редактируемые поля, поскольку клиент и установщик в этой версии рассчитаны именно на них.

### Доступы и пароли

В SSH показывается только выбранный способ входа: пароль пользователя **либо** приватный ключ и пароль ключа, если он есть. Учётная запись SSH нужна для управления VPS.

Откройте **Настройки → ДОСТУП VPN** (кнопка сверху). Строка доступа находится внутри блока Caddy. Сохранённый профиль автоматически показан точками; кнопка **Показать** раскрывает ссылку. Логин и пароль VPN находятся внутри этой ссылки:

- **Импорт JSON / ZIP** — открыть полученный профиль.
- **Строка доступа VPN** — вставьте полную действующую HTTPS-ссылку NaiveProxy прямо в поле.
- **Ввести логин / пароль VPN** — альтернативный ввод уже существующих данных. LETHE составит ссылку; отдельные дубликаты логина и пароля не сохраняются.
- **Для нового сервера** — создать случайный профиль для установки нового сервера. Эта кнопка не меняет пароль на существующем VPS. Профиль записывается только после сохранения настроек.

DuckDNS даёт имя нашему серверу. Пароль от аккаунта DuckDNS и его токен сюда не вводятся. Для SSH используются пользователь Linux/ключ, для VPN — данные из прежнего windows-01.zip или другого выданного профиля. Если профиль уже был сохранён под этим пользователем Windows, повторный ввод не нужен.

Если профиля нет, при установке нового сервера он будет создан автоматически. Для действующего сервера нужен действующий профиль. Домен в ссылке должен совпадать с полем «Домен Caddy». Для действующего VPS используйте прежний рабочий профиль: генерация других данных не восстанавливает доступ и не меняет пароль на сервере. Пароли сохраняются с защитой DPAPI текущего пользователя Windows.

## 3. Деплой: установка и проверка

Для существующего рабочего сервера достаточно **Проверить VPS**. Переустанавливать его ради обновления интерфейса не нужно.

Для нового сервера:

1. Подготовьте VPS: Debian 12/13 или Ubuntu 22.04/24.04 x86-64 с systemd. Вход — root или пользователь с sudo без пароля.
2. A-запись домена должна указывать на IP входа. У этой версии установщика не должно быть лишних A/AAAA-записей.
3. Разрешите входящие TCP 80/443 в панели хостинга и firewall VPS. SSH-доступ сохраните. Приложение не создаёт DNS-записи и не меняет входящие правила firewall.
4. Заполните блоки VPS/SSH и Caddy, включая email для сертификата. Сохраните настройки.
5. Откройте **Деплой**. При первом SSH-соединении сверится ключ сервера. Отпечаток получите в консоли хостинга: `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`. Для другого типа ключа используйте соответствующий файл.
6. После статуса «Сервер не установлен» нажмите **Установить сервер**. LETHE на этом ПК должен быть отключён.
7. Дождитесь результата и подключите VPN. Если сервер уже найден, повторная установка заблокирована.

## 4. Деплой: полное удаление компонентов сервера

Кнопка **Удалить сервер** поддерживает две наши установки: LETHE из выпуска 0.6+ и HTTPS Tunnel Lab 0.1 с дополнением устройств 0.2. Произвольный сторонний Caddy не удаляется.

1. Отключите LETHE и откройте **Деплой**.
2. Нажмите **Проверить VPS**, затем **Удалить сервер**.
3. Приложение прочитает состав установки и покажет адрес VPS, домен, службы, каталоги и учётные записи.
4. Для подтверждения введите показанный домен и нажмите **Удалить без восстановления**. До этого команда удаления не отправляется.
5. Дождитесь «Сервер удалён». Программа проверяет отсутствие компонентов после выполнения, а не только код завершения команды.

Удаляются службы и их автозапуск, файлы программы, сайт, конфигурация, сертификаты, доступы устройств, выделенные служебные пользователи/группы, собственная таблица выхода LETHE. Для старого HTTPS Tunnel Lab также удаляются агент мониторинга, его история и резервные копии проекта. Все клиенты, включая Raspberry Pi, теряют подключение.

Сохраняются SSH, сетевые адреса и обычные маршруты VPS, другие приложения, общие пакеты ОС и общий журнал systemd. Архивы, вручную скопированные пользователем вне каталогов проекта, не ищутся и не удаляются. Это удаление распознанного проекта, а не переустановка или очистка всей ОС.

При ошибке сообщение об успехе не появляется. Нажмите **Проверить VPS** и повторно запросите удаление: незавершённая операция имеет журнал и может продолжиться. Если файлы проекта заменены чужими, путь является символической ссылкой или внутри найдено монтирование, удаление блокируется. Подтверждение устаревает при изменении состава установки.

## 5. Сборка и проверка

Готовый `LETHE.exe` и библиотеки включены. Для пересборки на Windows запустите `BUILD.cmd`: используется компилятор .NET Framework, собираются EXE, библиотека полей и SSH-библиотека; выполняются локальные проверки.

Стандартный установщик NSIS собран: `LETHE-Setup-0.7.2-x64.exe`. Инструкция — INSTALL-RU.md. Для пересборки установите NSIS 3.09+ и выполните `BUILD.cmd -Installer`.

Проверки этого выпуска: `docs/TEST-RESULTS.txt`. Короткая проверка на вашем ПК: `docs/WINDOWS-CHECK.md`. Технические изменения и границы удаления: `ENGINEERING-NOTES-RU.md`. Графический интерфейс, UAC, DPAPI и удаление на реальном VPS в среде сборки не запускались.

## Исправления 0.7.1

- Исправлена ошибка «Replace с 3 аргументами: Путь имеет недопустимую форму» при повторной записи SSH-данных и профиля. Старые сохранённые данные не требуется удалять.
- Исправлен комплект зависимостей SSH: System.Buffers 4.6.1 и согласование версий DLL для LETHE.exe. Важно распаковать весь архив в новую папку, а не копировать только EXE.
- Ошибки деплоя теперь показывают этап и тип причины: загрузка компонента, отказ SSH-аутентификации, сеть/порт или приватный ключ. Пароли в сообщения библиотек не выводятся.
- После обновления сохраните настройки, откройте их снова и проверьте значения. Затем нажмите «Проверить VPS» в деплое. Для исправления клиента удалять или переустанавливать сервер не нужно.

## Исправление подключения 0.7.2

В присланном журнале запуск останавливался на вызове Windows SslStream.AuthenticateAsClient с ошибкой SSPI. NaiveProxy ещё не запускался. Убрана обязательная TLS-проверка через Schannel: она использовала другой TLS-стек, чем реальный движок VPN, и могла блокировать совместимое подключение.

Сначала проверяются TCP-доступность порта 443 и физический маршрут. Затем запускается NaiveProxy с обычной проверкой сертификата HTTPS-сервера. До включения TUN обязателен реальный HTTPS-запрос через его SOCKS и совпадение внешнего IP. Пустой ответ или неверный IP останавливают подключение с откатом. Защита сертификата не отключалась.

Внизу главного окна появилась кнопка **ЛОГИ**. Она открывает папку журналов и выделяет самый свежий журнал операции. При ошибке подключения также появляется окно с причиной и этапом. В заголовке новых журналов теперь правильная версия 0.7.2; строка 0.7.0 в журнале предыдущей версии была устаревшей подписью.

Для обновления закройте старую версию, полностью распакуйте архив в отдельную папку и запустите LETHE.exe. Настройки и профиль остаются в прежней папке данных. Сервер менять не требуется.
