# LETHE ONE: проверка исходной 0.5.14 и изменения 0.6.0

Дата: 13 октября 2026. Основа — предоставленный архив `LETHE_ONE_v0.5.14_TRAFFIC_FIX(1).zip`. Это аудит кода и проверки в Linux-среде. Замеры скорости на компьютере пользователя, запуск Windows GUI и установка на реальном VPS не выполнялись.

## Что в исходной версии сделано разумно

- NaiveProxy и sing-box разделены по функциям: транспорт HTTPS и системный TUN.
- До включения TUN проверяются конфигурация, прямой маршрут к VPS, TLS/SNI и выход через локальный SOCKS.
- Отдельный маршрут /32 к VPS предотвращает отправку самого транспорта обратно в TUN.
- При остановке скрипты проверяют путь исполняемого файла перед завершением процесса; чужие маршруты не удаляются произвольно.
- Пароль сохранён через DPAPI; временный файл NaiveProxy ограничен ACL и удаляется после загрузки.
- Счётчики входящего и исходящего трафика читаются отдельно из sing-box. При сбое выводится «н/д».

## Найденные ограничения и предложения

| Приоритет | Наблюдение в коде | Практическое следствие / предложение |
|---|---|---|
| Высокий | В `tun.template.json` SOCKS-outbound разрешает только TCP, а UDP явно отклоняется | Это системный туннель для TCP, с отдельной обработкой DNS. Обычный UDP, включая QUIC, игры и часть голосовых приложений, не поддерживается. Для полноценного UDP нужен отдельный транспорт и серверная поддержка; снятие правила reject этого не исправит. |
| Высокий | Guardian после серии сбоев удаляет TUN и возвращает обычные маршруты | Интернет продолжает работать напрямую. Это поведение fail-open, полноценного kill switch нет. Следующий этап — явный пользовательский выбор между восстановлением прямой сети и блокировкой интернета при потере VPN. |
| Высокий | Проверка доступности и выходного IP зависит от `api.ipify.org` | Сбой одного проверочного сервиса может остановить исправный туннель. Стоит разделить проверку процесса, TLS/прокси и IP, добавить несколько независимых контрольных адресов. |
| Средний | Автоматического переподключения после остановки Guardian нет | Полезны повторные попытки с увеличивающейся задержкой и ясный статус. Нельзя одновременно менять маршруты из нескольких фоновых обработчиков. |
| Средний | Чтение `/connections` возвращает и список соединений | Асинхронный запрос устраняет ожидание сети в UI, но объём JSON растёт с числом соединений. Следующий этап — отдельный сборщик агрегированных счётчиков с проверенным протоколом API. |
| Средний | Журналы накапливаются; клиентская служба Windows отсутствует | Нужны ротация журналов и, для стабильного продукта, отдельная служба с ограниченным IPC. Это позволит лучше отделить UI от привилегированных операций. |
| Средний | Бинарные движки были просто вложены в архив | Нужны управляемые обновления с закреплёнными версиями, проверкой хешей и откатом. В этой версии рабочие движки намеренно сохранены побайтно. |

По одному исходному коду нельзя обоснованно обещать прирост пропускной способности. Настройку MTU, буферов и числа соединений следует выбирать после измерений на той же линии и VPS, сохраняя нагрузку одинаковой.

## Что изменено

- «Информация» заменена на «Деплой». Для существующего сервера отображается «Сервер установлен», кнопка установки неактивна.
- Сетевые параметры, импорт профиля, логин/пароль VPN, параметры SSH, email TLS и настройки окна собраны в одном окне настроек с разделами.
- Добавлен отдельный процесс SSH-деплоя: окно не ждёт окончания удалённой команды в своём потоке. Есть этапы, конечный результат и таймаут.
- SSH.NET 2026.0.0 и его зависимости включены; парольный вход и приватные ключи OpenSSH/PEM поддерживаются. Пароль/ключевая фраза защищены DPAPI. Доверие к ключу сервера сохраняется и проверяется для SSH и SFTP.
- Поля пользователя передаются на сервер JSON-данными в закрытом каталоге, а не подставляются в shell-команды. Установка защищена от двух одновременных запусков локально и на VPS.
- Статус не берётся из постоянной галочки на клиенте. Он запрашивается по SSH. Изменение настроек и истечение пяти минут требуют новой проверки. Внутри установки VPS проверяется ещё раз.
- Установка рассчитана на Debian 12/13 и Ubuntu 22.04/24.04 x86-64 с systemd. Зависимости скачиваются через apt, сервер — из официального релиза Caddy/NaiveProxy v2.11.7-naive с закреплённым SHA-256.
- Создаются отдельные службы и каталоги LETHE, а не заменяется найденный чужой Caddy. Для двух IP SNAT ограничен исходящими соединениями отдельного пользователя службы. IPv6-выход этого сервера ограничен семействами сокетов службы; эта версия развёртывания рассчитана на IPv4.
- После запуска проверяются HTTPS с валидным сертификатом, авторизованный CONNECT, заданный IP выхода и HTTP-отказ анонимному CONNECT. Установка не считается успешной только по `systemctl active`.
- При ошибке после создания служб выполняется откат принадлежащих этой попытке ресурсов. Пакеты apt остаются. Частичный откат не выдаётся за успех.
- Данные перенесены в `%LOCALAPPDATA%\LETHE-One`. Исходный DPAPI-профиль сохраняет расположение. Это позволяет устанавливать файлы программы в Program Files.
- Запрос статистики sing-box переведён на асинхронный HttpClient, конфигурация API кэшируется на сеанс; ответ ограничен 8 МиБ. Изображение шапки больше не удерживает забытый MemoryStream.
- Добавлен автоматический выбор физического интерфейса при пустом поле. Поправлены обработка брошенного mutex и атомарная замена профиля. В главном окне стали видны сообщения операций.
- Собран x64 `LETHE.exe` — небольшой .NET Framework 4.8 launcher существующего GUI, без PS2EXE. Исходники и скрипт пересборки приложены. Подготовлен сценарий Inno Setup; Setup.exe не собирался.
- Старые runtime-файлы и журналы из исходного ZIP не включены в новый выпуск.

## Проверки

| Проверка | Результат |
|---|---|
| Синтаксис всех PowerShell-скриптов парсером PowerShell 7.6.6 | Пройден; использован синтаксис, совместимый с Windows PowerShell 5.1. Отдельный прогон именно 5.1 предусмотрен BUILD.cmd. |
| Компиляция EXE и SSH-библиотеки по reference assemblies .NET Framework 4.8 | Пройдена. EXE имеет x64 GUI PE, версию 0.6.0.0 и встроенный manifest asInvoker. |
| Python unit tests установщика | 14 проверок пройдены: валидация, запрет повторной установки, занятый сервер, DNS, права файлов при umask 077, хеш загрузки, безопасное кодирование данных и параметры SNAT. |
| Реальный Caddy из закреплённого архива: adapt/validate, локальный TLS и CONNECT | Авторизованный запрос передал тестовые данные; анонимный получил HTTP 404. Тест использовал локальный сертификат и loopback-цель; публичный ACME не проверялся. |
| SSH на локальном тестовом сервере | Проверены чтение fingerprint без доверия, отклонение несовпадающего ключа, парольная аутентификация, приватный Ed25519-ключ, выполнение команды, SFTP и права 0600. Для Linux-стенда использована net10-сборка той же версии SSH.NET; комплект net462 проверяется на Windows через BUILD.cmd. |
| Бинарные движки | NaiveProxy, sing-box и Wintun совпадают с исходным архивом по SHA-256. Wintun 0.14.1 дополнительно совпал с официальной AMD64-библиотекой. В Go build info sing-box указана версия 1.14.2. |
| Windows GUI, UAC, DPAPI, реальный TUN, публичный TLS/ACME, systemd/nftables на VPS, перезагрузка VPS, установщик | Не выполнялись в этой среде; нужны проверки из WINDOWS-CHECK.md. |

Важные границы: распознавание старого сервера по активному Caddy с модулем forward_proxy не подтверждает правильность введённого профиля; недоступный или нестандартный старый сервер может отображаться как конфликт. «Установлен» и «доступен для передачи трафика» — разные состояния. При обрыве SSH установщик может продолжить работу на VPS; повторная проверка состояния обязательна.
