# LETHE 0.7.2 — инженерные изменения

## Настройки

`scripts/Settings-Panel.ps1` — единственная форма редактирования. Блоки VPS/SSH, Caddy, приложение находятся в прокручиваемом окне. Общие IP выбираются ссылкой на адрес VPS или входа; отдельные поля показываются только для отличающихся адресов. На диске сохраняются разрешённые значения в прежнем формате, поэтому сетевые компоненты и старые настройки совместимы.

Поля `Lethe.RoundedField` — собственные контейнеры WinForms с закруглённой рамкой, тёмной заливкой и обычным текстовым редактором внутри без стандартного бордюра. Подсказки назначены контейнеру, редактору и подписи. Кнопки навигации перемещают к блоку; нижняя панель сохранения не прокручивается.

VPN-учётные данные представлены защищённым профилем, а не двумя ручными полями. SSH-учётные данные сохраняют прежний формат DPAPI и показываются по выбранному способу входа. Отпечаток SSH доступен для просмотра/сброса доверия; при смене адреса или порта доверие сбрасывается.

## Приложение без консоли

`src/AppHost.cs` собирается в Windows x64 GUI executable. Встроенный Windows PowerShell 5.1 исполняет скрипты в процессе LETHE через STA runspace на текущем потоке. Отдельный powershell.exe для интерфейса и рабочих операций не создаётся. Используется процессная политика исполнения, как в прежнем запуске; политики Windows Group Policy сохраняют приоритет.

Режимы EXE: окно, `--action start|stop|status`, `--guardian`, `--deploy status|install|remove-plan|remove`. Параметры проверяются по закрытым спискам и формату, произвольные команды или пути запускать нельзя. Деплой получает секреты из локального DPAPI, не из командной строки.

Подключение/отключение запускают другой экземпляр того же GUI EXE с UAC. Guardian тоже работает в EXE; остановка проверяет путь процесса и точный режим `--guardian`. Переиспользованный PID другого процесса не принимается. Старый скриптовый guardian распознаётся отдельной веткой для совместимости.

NaiveProxy использует CreateNoWindow, как раньше. sing-box запускается через `CreateProcessW` с `CREATE_NO_WINDOW` и наследуемыми файловыми дескрипторами журналов; журналы продолжают работать после завершения START-процесса. Это важно: асинхронные обработчики stdout в короткоживущем START-процессе не обеспечили бы сохранение журнала после его выхода.

Короткие проверки curl и конфигурации sing-box также явно запускаются с CreateNoWindow и ограничением времени. Проверка локального SOCKS принудительно отменяет NO_PROXY, чтобы не обойти проверяемый канал из-за переменных окружения.

## Удаление сервера

`server/removal.py` содержит два фиксированных состава установки. Пути от клиента не принимаются. Принадлежность проверяется по маркерам проекта, служебным путям, командам запуска служб и выделенным пользователям. Символические ссылки в корнях, вложенные точки монтирования, заменённые службы и совместно используемые учётные записи блокируют удаление.

`remove-plan` выполняет проверку и возвращает состав плюс SHA-256 токен состояния. `remove` повторно строит план, сверяет токен и подтверждённый домен. Изменения после просмотра плана останавливают операцию до удаления. Оба семейства команд сериализованы блокировками LETHE и старого HTTPS Tunnel Lab.

Сначала отключаются службы, затем проверяется остановка, удаляется только собственная nftables-таблица, удаляются каталоги/автозапуск/доступы, выделенные пользователи и группы. Отсутствие файлов, служб, учётных записей и таблицы проверяется отдельно. Неполное удаление оставляет защищённый журнал `/var/lib/lethe-removal/state.json`; после успеха удаляется и он. Повторная операция допускается только для оставшихся объектов исходной установки.

Общие пакеты ОС и systemd journal принадлежат всей системе, поэтому не удаляются. Отдельные вручную сохранённые копии/архивы вне зарегистрированных каталогов проекта также не затрагиваются. На настоящем VPS в этом выпуске удаление не выполнялось.

## Ограничения транспорта

Эта версия меняет интерфейс, запуск и управление сервером. Ограничения прежнего сетевого транспорта сохраняются: обычный UDP не обеспечен, полноценного kill switch нет. При аварийном отключении может восстанавливаться прямое соединение. Старый сервер также может ограничивать TCP-порты назначения. Настройка TUN не отменяет серверные ограничения.

## Проверка и источники

Актуальные проверки — `docs/TEST-RESULTS.txt`. Исторический аудит 0.6.0 лежит отдельно в `docs/history` и не выдаётся за повторно выполненные испытания.

- Microsoft: https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo?view=netframework-4.8
- Caddy, Automatic HTTPS: https://caddyserver.com/docs/automatic-https
- Caddy, хранение данных и сертификатов: https://caddyserver.com/docs/conventions

Reference assemblies PowerShell/.NET Framework использованы только при сборке. В архив они не включены; EXE использует встроенные компоненты Windows. Подпись EXE и установщик не подготовлены этим выпуском.

## Исправления 0.7.1

PowerShell преобразовывал $null в пустую строку в третьем строковом аргументе File.Replace. Это воспроизведено на реальных временных файлах. Storage.ps1 передаёт [NullString]::Value; этот путь используется при замене обоих DPAPI-файлов. Тест проверяет создание, повторную замену и сохранность старых данных при ошибке. Windows DPAPI-проверка приложена, но на Linux не запускалась.

В 0.7.0 System.Buffers имел assembly version 4.0.3.0 при требовании 4.0.5.0 из SSH.NET и других зависимостей. Пакет заменён на 4.6.1, DLL 4.0.5.0. Update-Bindings.ps1 генерирует LETHE.exe.config с probing lib и redirect на реально поставляемые версии. Test-DependencyBindings.ps1 проверяет 29 межбиблиотечных ссылок; более старый, чем требуется, DLL приводит к ошибке теста. Это исправляет подтверждённое несоответствие сборки, но успешное подключение к пользовательскому VPS не утверждается.

В настройках один источник VPN-данных — скрытая строка профиля. Ручной ввод логина/пароля преобразуется в эту же строку с URI escaping. Изменение локального профиля не меняет серверный пароль. Библиотечные исключения деплоя раскрываются до внутреннего типа; в интерфейс попадают понятная категория, этап и код типа, а не исходное сообщение с потенциальными секретами.

## TLS-проверка 0.7.2

Причина остановки установлена по пользовательскому логу: исключение AuthenticateAsClient/SSPI, до naive-process-launch. Точный внутренний код SSPI в старом журнале отсутствует; конкретная причина согласования TLS не доказана. Удалён отдельный Schannel TLS preflight, сохранены проверка TCP/физического маршрута и обязательная HTTPS-проверка через фактический NaiveProxy до TUN. Проверка сертификатов в конфигурации NaiveProxy не ослаблена.

EXE получил TargetFrameworkAttribute .NETFramework 4.8. В журнале поправлена версия, установлен Out-File Width 4096, ошибка и этап сохраняются в last-action.json даже после очистки state.json. UI показывает ошибку и кнопку папки журналов.

Справочные материалы: https://learn.microsoft.com/en-us/windows/win32/secauthn/protocols-in-tls-ssl--schannel-ssp- и https://learn.microsoft.com/en-us/dotnet/framework/network-programming/tls . Поддержка TLS в Schannel зависит от Windows и не описывает возможности TLS-движка NaiveProxy.
